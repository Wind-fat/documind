# ADR-0005 切块：四种策略并存，用同一评测集选型

- 状态：已采纳（2026-11）

## 背景

"我们做了分块"是简历里最没有信息量的一句话。切块策略直接决定 Recall@K 与 faithfulness，
而它没有普适最优解——取决于语料结构。制度/条款类文本与新闻、代码的答案边界完全不同。

## 决策

一次入库同时产出四种切块（`chunks.strategy` 区分），评测时只换 strategy，其余链路完全一致：

| 策略 | 做法 | 预期强项 | 预期弱项 |
|---|---|---|---|
| fixed | 512 字滑窗，50 字重叠 | 简单、块长可控 | 条款被切断，答案拼不回来 |
| semantic | 句子向量相邻相似度 < 0.62 断开 | 话题边界自然 | 与"条款"边界不一致，短块噪声多 |
| structure | 按 章/节 分组，条为原子单位，≤900 字 | 答案完整、可解释 | 块偏长，长块稀释相似度 |
| parent_child | 子块 ~200 字召回，父块 ~900 字喂模型 | 召回精确 + 上下文完整 | 存储翻倍、实现复杂 |

## 为什么"条为原子单位"是关键

一个条款被劈成两半后，模型只看到"…工作满十年者享有十天"而看不到前半句的"年假天数"，
faithfulness 直接掉。这是 structure 策略在本语料上胜出的机制性原因，不是调参运气。

## 结论从哪来

见 `evals/reports/ablation.md`：同一批 100 条问题、同一套混合检索 + 重排 + 生成，
只换 strategy 的 Recall@5 / Context Recall / Faithfulness / 误拒率 / P95 延迟 / 单问成本。

## 放弃了什么

- 基于标题的小块 + 无父块的组合（召回高但上下文碎）。
- 固定 token 数切分（中文按 token 切分需要分词器，且与"条"边界无关）。

## 已知限制

- 语料是 3 份公司章程（166 页），结论不可直接外推到合同、代码、工单类语料。
- 父子块让存储与 embedding 成本约翻倍，需要在部署时说明。
