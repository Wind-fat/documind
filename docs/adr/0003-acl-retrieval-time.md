# ADR-0003 权限：ACL 在检索阶段生效，不是生成后过滤

- 状态：已采纳（2026-11）

## 背景

企业知识库里必然存在"财务制度只有财务能看""人事制度只有 HR 能看"的文档。
常见实现是：先检索全部文档 → 生成答案 → 再把用户无权的内容从答案里删掉（或提示"你没有权限"）。

## 决策

文档级 ACL 存在 `documents.acl_roles`（角色数组，`["all"]` 表示全员可见）。
检索时先把当前角色的可见文档集合算出来，**在 BM25 打分与向量相似度计算之前**就把无权 chunk 的行剔掉
（`index.BM25Index.search(..., allowed=...)`、`VectorIndex.search(..., allowed=...)`）。

## 为什么不能后置过滤

1. **内容会泄露**：模型读过无权文档，答案里可能出现"据财务制度第五条规定…"这种原文复述。
2. **日志会泄露**：检索 trace 里记录命中的 chunk 与原文片段，做后置过滤时这些已经写进日志与 Langfuse。
3. **无法解释**：用户看到"有 3 条证据但都被隐藏"，本身就是在泄露存在性。

## 实现细节

- 无权文档在 `GET /documents/{id}/pages/{n}` 返回 **404 而不是 403**——不泄露"某文档存在"这一事实。
- 检索为空与"检索到但无权"给出**同一条拒答理由**，不区分。
- 测试 `test_retrieval_respects_document_acl` 断言：employee 角色下，财务文档的 chunk 既不在 hits 也不在 contexts。

## 放弃了什么

- 行级/字段级 ACL（比如同一文档里"薪酬章节"更敏感）。当前粒度是文档级，P1 再做。
- 多租户隔离。当前单租户，租户维度会加在 `documents.tenant_id` 上并在索引侧分片。
