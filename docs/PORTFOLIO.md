  而 Context Recall 从 0.75 提到 0.95、Faithfulness 从 0.834 提到 0.938** —— 结论是"切块改的是上下文完整度，不是召回率"

## 面试追问清单（每题都要能翻到代码位置）

1. **为什么不直接用 Dify/FastGPT？** —— 先承认它们解决"快速搭建"；再说 PoC 后三个点不可接受：
   ACL 粒度、拒答判定、切块策略改不动 → 所以下沉到代码层（`docs/adr/0003`、`0004`、`0005`）。
2. **评测集是不是自欺欺人？** —— `evals/README.md` 的构建方法 + 已知限制：合成题、无 holdout、
   judge 与被测同模型。主动说这三条限制，比被问出来强。
3. **10 万页怎么办？** —— 索引增量（sha256 + 文档级 rebuild）、分片（按部门/租户）、
   检索分层（粗排 200 → 精排 20）；当前 dev 是进程内索引，检索后端有注入点
   （`IndexStore.get(keyword_builder=, vector_builder=)`），换 pgvector/OpenSearch 只动实现，
   但组装与列类型仍要改（ADR-0002 §切换成本）。
4. **引用为什么能定位到 span？** —— 解析阶段保留页内字符偏移，块文本由 `slice_text` 生成（有测试钉住），
   回答后 quote 回查原文页拿真实偏移（`generate.locate_quote`），定位不到就退回块级 span，
   **绝不返回假偏移**。
5. **权限为什么必须在检索阶段？** —— 后置过滤会同时在答案和日志里泄露；
   看 `test_retrieval_respects_document_acl` 与 `test_hidden_document_is_404_not_403`。
6. **幻觉率怎么控制？** —— 三道：上下文约束、引用逐字校验、自检重试；
   实测数字在 ablation 报告里（faithfulness + false_refusal_rate）。
7. **换模型会死吗？** —— 改 3 个环境变量（`docs/INTEGRATION.md`，可指到项目三 AIGate）。
